# claudex-loop：双模型审查机制

GitHub 这一年冒出几十个大模型编码自我纠错的项目。大家都烦 Agent 没有验证机制，跑着跑着就死循环或者跑偏。今天看的是 chaseai-yt/claudex-loop，Trendshift 把它标成了 AI coding assistant，现在 2929 星。它想用双模型交叉审查来解决这个问题。

翻文档和代码痕迹，claudex-loop 给了挺具体的命令行参数。SkillsLLM 文档写着能用 `-m, --max-iterations`（默认 20）控制循环，`-d, --done`（默认 DONE）设完成信号，还能用 `--review [claude|codex|claudex]` 调审查模型。GitHub Actions 里有 CI 记录，提交 4b21efb 跑了 Validate #6，33 秒，里面有 codex/lightweight-router 测试。作者在主页把这玩意定义成四阶段计划强化技能，包括侦察、审问、Codex 对抗。说白了就是两个模型交叉审查计划，然后互换角色。

这工具是有真工程含量的，不是随便拿提示词包一包。看退出信号怎么设的、迭代上限能不能配，还有带 lightweight-router 这类组件的 CI 测试就知道。

跟同类项目比，claudex-loop 跟同作者的 crucible 重合度很高，它算完整循环版。DanMcInerney/architect-loop（625 星）和 finna/Finn-loop（319 星）侧重点不太一样，zarazhangrui/codebase-to-course（5672 星）定位就完全不同了，主要是生成学习课程。如果是要对方案做硬审查的算法开发，用 claudex-loop 挺合适。

缺点也很明显，循环机制太费钱。YouTube 上有视频提到，Agent 一直重新评估，特别费 token，很容易就超量。HN 上聊 loop prompts 的时候，也说这种机制拿去克隆商业软件有争议。而且 README 拉取失败，文档不全，普通人上手挺费劲。

这工具就是拿来做硬性约束的，不能由着 Agent 乱跑。
