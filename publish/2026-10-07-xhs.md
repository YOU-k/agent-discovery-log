# 拆解 anti-ai-slop：流水线去 AI 味的实现逻辑

现在大模型写代码和文章多了，到处都是那种一眼假的“AI味”文本。过去一年 GitHub 上冒出不少想解决这个问题的项目。misbahsy/anti-ai-slop 就是其中一个，这是个给 Claude Code 用的技能项目，主要用来揪出并改掉文字里的 AI 味。

这个项目的 README 没抓到，只能靠追踪数据和网上的背景信息来拆解。看 mcpmarket 的说明，这个工具相当于个自动审查员，专门识别并干掉 AI 助手带来的低价值模式，比如没用的冗余注释。我们的追踪数据发现它搞了个多关卡流水线。不光负责改写，改完还得过四道自动验收关卡来保证去味效果。

这不是随便弄个提示词包装就完事。普通提示词只会让模型改一次，这个项目加了四道自动验收关卡，成了个带反馈和验证的流水线。这种多步检查的设计，确实有点工程化的意思。

跟同类项目比，区别主要在验收机制。blader/humanizer 这种只做单次改写，anti-ai-slop 硬是多出四道自动验收关卡。再看其他技能项目，zarazhangrui/codebase-to-course 专门生成学习课程，ythx-101/live-panel-skill 搞动态架构图。wilbert-MD-PhD/medical-illustration 做医学插画且有据可查，viettranx/3dviz-pro-max 搞 3D 可视化。anti-ai-slop 就死磕文本去味的验证环节。

局限也很明显。flaviocopes 博客提到，反 AI 味技能顶多抓抓模式，补不了缺失的事实，也定不了正确的架构。scsynth 论坛那边有人讨论，觉得“反 AI”这阵风刮得太大，容易让人看低别人真实的劳动。工具去味有上限，事实核查和逻辑构建它替不了。

去 AI 味还是得靠系统工程化的约束，这也是这个项目最实在的价值。
