# 拆解 ai-slop-detector：检测 AI 套话的技能库

现在大模型写的文字和代码太多了，空泛内容、模板套话、看着完整但跑不通的代码到处都是。学术界沾上这股AI味就丢严谨性，工程界里假文档和空函数也带来一堆维护负担。今天看的 FeedHive/ai-slop-detector 项目，就是冲着这个去的。

想从仓库扒 README 看看具体实现，但抓取失败了。所以它到底有没有跑得通的命令、规范的文件结构，还有 scripts、tests 或 CI 这些工程化配置，都不好说。从现有追踪数据看，它核心是个 Claude Code skill，专门检测和抹掉文章里的AI套话。

README 没抓到，加上它只是个 Claude Code skill 的定位，这项目大概就是个提示词包装或者配置文件，谈不上有复杂静态分析或能独立运行的真实工程。对比之前提到的 flamehaven01/AI-SLOP-Detector，人家明确是个基于证据的静态分析器，真能揪出空函数和假注释，有工程深度，FeedHive 这个就轻得多了。

跟同类比，misbahsy/anti-ai-slop 做了多道自动检查的流水线，FeedHive 只是技能集合。去AI味这块，它比 humanizer 成体系点，直接对着AI通病改论文，不过防重复机制跟 humanizer、humanizer-zh 差不多。别的像 ythx-101/live-panel-skill 搞动态数据流图表，xianyu110/ecommerce-video-skills 做电商视频，跟文本去味完全不搭边。

最大的短板是工程不透明。没 README，用的人根本不知道检测靠的是启发式规则还是大模型判定。HN 上也有人讨论说 YouTube 的 AI slop detector 误伤过 Kurzgesagt 频道，说明这种靠模式匹配的工具很容易乱判，敏感度跟准确率怎么平衡还是个麻烦事。

现在大家都用AI辅助写作，这种工具勉强能当个初步去味方案，靠不靠谱还得开发者自己验。
