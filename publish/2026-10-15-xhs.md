# 拆解 grill-with-ui：如何补齐结构化提问短板

多数 AI 辅助编程技能包都在卷“给答案”，也就是直接生成代码，不怎么管“怎么提问”。遇到设计或架构分歧，编码代理只能靠纯文本反复猜。处理空间、视觉或交互问题，这种方式效率很低。今天看的 jasonku09/grill-with-ui（2026年9月20日星数294，日均涨星8）想补上“结构化提问”这块。

项目 README 拉取失败，没法看文件结构、scripts 或 CI 配置这些工程细节。看 FakeNerd.ai 的网络讨论和追踪数据，它的做法是把 Claude Code skill 里的代理提问环节拽出来，放到浏览器卡片上。应用界面最右侧一栏支持直接提问和向下钻取细节，能多线程回答，随时改，最后打包发回代理。其实就是把 Matt Pocock 提出的“grill-me”纯文本提问做成了可视化 UI。

看现有素材，它更像是交互形态的转换和提示词包装，不是从零搭底层设施。前端卡片重塑了人机问答流，这点有价值。不过受限于素材，没看到复杂系统级工程或测试体系的验证。

拉个同类型项目对比，定位差别挺明显。dominikmartn/nothing-design-skill 负责按特定风格生成网页 UI 代码，OpenLabs-so/oa-design 专门做数据看板类前端设计，Desertbetweenalembic/website-downloader 则偏向逆向克隆网站和架构文档。这几个项目还是在输出具体产物。grill-with-ui 不一样，它给需要反复推敲方案、整理思路的开发者提供了一套交互框架。

局限也明显。太依赖前端交互，没看到测试和 CI 证据，放到复杂项目里稳定性存疑。另外，GitHub Issue #336 里讨论 grill-with-docs 时也提到，什么时候用 UI 原型代替文本问答，现在还没个定论。

工具到底怎么演进，光堆算力可能不够，交互界面的重新设计可能才是重点。具体效果还得再观察。
