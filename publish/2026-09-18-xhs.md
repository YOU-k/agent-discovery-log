# 拆解 neuroarxiv：动手前先查 arXiv 先例

做算法的应该都碰到过这种事：新问题一来，撸起袖子就开始写架构调参数，几周后才发现 arXiv 上早有人做过，结论还是此路不通。不是能力问题，是"先查先例"这一步压根没进工作流。neuroarxiv 想补的就是这个环节。项目 2026-08-28 首次进我们的追踪列表，当时 424 星，日均涨星约 1。

它的主张写在项目描述里：让 Claude 设计新架构之前，先去查 arXiv 上的真实已有工作，原话是 "kill from-scratch coding"，LinkedIn 上的分享也引了这句。比起通用的找文献技能，它的定位更窄，只盯"动手前查先例"这一个动作。

具体怎么落地？README 抓取失败，能拿到的直接证据都在安装环节。项目给了一条显式安装命令：npx github:UditAkhourii/neuroarxiv install --codex。文档说，目标环境需要无视自动检测、强制安装时，可以显式固定目标；另外 CLAUDE_CONFIG_DIR 和 CODEX_HOME 这两个环境变量会被尊重，用来保留自定义配置目录。能读出两点：一是它同时面向 Claude Code 和 Codex 两类运行环境，二是安装器会做环境探测，也允许用户覆盖探测结果。技能内部的提示词结构、有没有 scripts 目录、有没有测试或 CI，现有素材里没有可引用的证据，判断不了。

工程含量上看，这是个以技能描述和安装脚本为主的轻量项目，更像技能声明加安装配置的封装，不是带完整测试链路的工程项目。两条依据：可核验的内容集中在 npx 安装命令和环境变量处理；素材里没有任何 scripts、tests、CI 的记录。这跟作者背景也对得上，他 GitHub 主页显示是在印度理工学院读计算机科学的学生，研究 AI 的替代认知架构。同一位作者还有个开源技能 adhd，两阶段发散式构思，在不同认知框架下并行发多个 LLM 调用，说明这是一条持续产出技能的工作线，不是单点项目。
