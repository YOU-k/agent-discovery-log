# 拆解 Anthropic 办公插件：真实工程还是包装

过去一年大家都在试怎么把大模型塞进日常办公里。模型虽然通用，但不懂各岗位的专有工具，也不懂团队内部的规矩。Anthropic 开源的 knowledge-work-plugins 就是冲着这个去的。目前星数 32616，每天涨星一千多，外网博客说它是科技团队必备。

README 里写了，它给 Claude Cowork 和 Claude Code 提供了 11 个插件，管销售、法务、财务这些。底层靠标准化目录结构实现。插件包含 `.claude-plugin/plugin.json` 清单、`.mcp.json` 配置、`commands/` 目录放斜杠命令，还有 `skills/` 目录放领域知识。装的时候先跑 `claude plugin marketplace add anthropics/knowledge-work-plugins`，再跑 `claude plugin install sales@knowledge-work-plugins`。装完特定场景会自动触发，比如敲 `/sales:call-prep` 就能直接调。

这不是随便塞点提示词就算了，有真工程量。模块分得很清楚：Skills 存专业知识和工作流，Commands 给调用接口，Connectors 通过 MCP 服务器连 Slack 和 Jira。把知识、命令和外部工具绑在一起，这才跑通了智能体工作流，光靠文本交互是不够的。

跟同类项目比，定位不太一样。`anthropics/claude-plugins-official` 算是个官方插件索引；`cursor/plugins` 偏开发和学习；`wentorai/research-plugins` 搞科研。knowledge-work-plugins 则是死磕企业办公，直接对接具体岗位用的那些 SaaS。

麻烦的地方在于企业自己部署起来要改的东西太多。README 说支持自定义，但要把通用插件套进自家公司的术语和流程里，还得调很久。而且它很依赖外部 Connectors，企业得先把自己内部的 API 和数据权限理顺才行。

Anthropic 给了套现成的脚手架，但要把通用模板塞进企业的私有流程里，还是得花大力气做工程改造。
