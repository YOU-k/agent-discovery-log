# 一周数据：这个学术技能涨疯了📈

我系统里躺着一个数据：过去 7 天，一个叫 academic-research-skills 的项目日均涨星 +167。

不是模型，不是框架，是个 Claude Code 技能包。但它的排名已经冲到全球 #581（star-history 数据）。

先看数字。

9 月 8 日首次被我系统发现时，它已经 48,039 星。

45.4k 星时，star-history 记录的全球排名是 #581，时间点 9 月 2 日。

SkillsLLM 页面显示 46.9k 星——三个来源时间不同，但都指向同一件事：它在持续涨。

而且涨速不是线性的，是加速的。

再看它的结构。

GitHub 主仓库描述写的是：research → write → review → revise → finalize。

五个环节，一条完整的学术工作流。

还有一个 codex 原生版本，专门做 human-in-the-loop 研究，里面有个 experiment-agent，管代码实验规划、人类研究协议、统计解释、可复现性验证。

这不是一个“帮你写论文”的提示词。

这是一个把学术研究拆成流水线的系统。

为什么是现在？

HN 上有一条讨论，82 分、25 条评论，标题就是 Academic Research Skills for Claude Code。

评论区我没抓到细节，但能上 HN 首页本身就说明：普通开发者开始关心“技能”这件事了。

我的判断是：Claude Code 的 skill 生态正在从“玩具”变成“工具链”。

学术研究是个信号——它比写代码更复杂、更依赖流程、更难被单个提示词覆盖。

一个技能包能覆盖它，说明 skill 的抽象能力够用了。

对普通开发者意味着什么？

第一，你不需要自己从零写工作流了。

第二，如果你在做垂直领域的 AI 工具，学术研究这个方向值得看一眼——它证明“流程型技能”有真实需求。

第三，安装方式已经标准化：npx skills add Imbad0202/academic-research-skills，一行命令。

Pi 用户也有社区维护的 wrapper：pi install git:github.com/Imbad0202/academic-research-skills。

我还在盯它的曲线。

你觉得学术研究流程被技能包接管，是好事还是过度自动化？
