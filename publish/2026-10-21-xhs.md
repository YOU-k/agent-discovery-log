# 拆解 tutor-skills：构建知识内化闭环

看 PDF 和开源代码容易看完就忘，光做笔记不测验也没用。bevibing/tutor-skills 拿了 1359 颗星，思路是把学习材料转成 Obsidian 库再自动出题。AI Skill Market 之前也提过这类需求。

项目里主要两个 Claude Code skill。跑 /tutor-setup，工具先看目录里有没有 package.json。有就走 Codebase Mode，没有就进 Document Mode。Document Mode 会扫 PDF、TXT、MD 这些文件，过 D1 到 D9 九个阶段，生成带 00-Dashboard 和编号主题文件夹的 StudyVault 结构，用 wiki-links 互链。另一个 skill 是 tutor，跑 /tutor 就基于刚才的 StudyVault 测验，一轮 4 道题，按答题情况更新进度。

看代码结构，这项目主要靠提示词定义工作流，没什么底层代码。核心逻辑全压在 Claude Code 的执行能力上。仓库里没 tests 目录，没 CI，只有一个手动装的 install.sh。

几个同类项目方向不太一样。hkcanan/katmer-code 把多模型聊天塞进 Obsidian，适合在笔记里对比模型。zarazhangrui/codebase-to-course 生成 HTML 交互课程，偏代码库教学。yunshenwuchuxun/latex-paper-skills 管的是 LaTeX 论文写作。ythx-101/live-panel-skill 专注 JSON 到动态架构图的转换。tutor-skills 带复习和 Obsidian 输出，更偏向个人学习与知识内化场景。

作为提示词工程产物，生成质量很看底座模型。处理大型代码库时，D1 阶段扫描可能会因为上下文窗口截断信息。自动生成的笔记结构也未必符合个人习惯，还得自己多调。

这套知识内化的工作流可以拿来参考，但指望它全自动开箱即用不现实。
