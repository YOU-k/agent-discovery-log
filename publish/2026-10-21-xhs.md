# 拆解学术论文技能：它是真实工程吗

过去一年 GitHub 上冒出不少想用大模型重写科研流程的项目。大模型搞长文本一致性容易翻车，文献追溯也弱，光靠提示词很难写出结构严谨的学术稿。今天看的 lishix520/academic-paper-skills 拿了 1414 颗星，被 SkillsLLM 网站收录了，方向是用 Claude Code 写哲学和跨学科论文。

项目核心是个双技能工作流，academic-paper-strategist 管规划，academic-paper-composer 管写作。安装不复杂，把 strategist 和 composer 目录扔到 ~/.claude/skills/ 下就行。目录结构挺规整，SKILL.md 是主定义，配 references 参考文档和 scripts 脚本。规划阶段靠 evaluate_samples.py 和 gap_analysis.py 扒样本、找研究空白；写作阶段换 chapter_quality_check.py 和 final_evaluation.py 做评估。它搞了个 7 维度 35 项的审稿人模拟系统，大纲评分过 28/35 阈值才放行进入写作。整个流程下来有 3 个验证关卡和 2 个 Python 验证脚本。

这项目有点真东西，不是套个提示词壳子。它用 Python 脚本做客观检查，提示词、文档和脚本也按职责拆进了不同目录。加上硬性的数值阈值阻断，分数不够不让往下走。这种带状态控制的流程，早就不是单次提示词交互能比的了。

和同类比，定位区别挺大。AAASS554/codex-academic-paper-skills 奔着本科软工毕业论文去，搞了中文降重和降 AIGC 检测。Boom5426/Nature-Paper-Skills 攒了 27 个投 Nature 系的技能，盯着证据边界和图注审计。lishix520 这个则死磕多轮审稿人模拟，适合需要学特定平台风格（比如分析 8-10 篇样本）的研究者。

看下来它和已有的 Imbad0202 学术技能功能重叠挺多，差异不算强。虽然有 Python 脚本，但没看到测试文件或 CI，脚本到底稳不稳还得再看看。项目日均涨星 3 个，不温不火。

用大模型写学术稿，加代码验证和多轮评分算是个路子。不过怎么跟同类项目拉开差距，大概是它接下来得头疼的事。
