# 拆解 Headroom：AI Agent 的上下文压缩层

GitHub 上处理 AI Agent 上下文膨胀的项目挺多。Agent 调工具、读日志、拉 RAG 数据，Token 很容易爆。Headroom 想在数据进模型前先压一道，把 Token 降下来，同时尽量不伤回答质量。

README 里列了四种集成方式：compress(messages) 函数、零改动代理模式 headroom proxy --port 8787、包装器 headroom wrap claude|codex|grok，还有标准 MCP 服务（带 headroom_compress 等三个工具）。内部组件看得出花心思：处理 JSON 的 SmartCrusher、基于 AST 的 CodeCompressor，外加跑自然语言的 HuggingFace 模型 Kompress-v2-base。Python 和 TypeScript 都支持，CI 走 GitHub Actions，发到了 PyPI 和 npm。

这不是单纯套个提示词的项目。架构里塞了 CacheAligner、ContentRouter 和可逆压缩缓存（CCR），支持 Docker 部署。headroom learn 功能值得提一句，能把跑废的会话扒出来，把修正写进本地标记文件。

横向比一下，定位各有侧重。caveman 让 agent 说原话，硬砍 65% Token，跟 Headroom 撞车严重。token-diet 盯着会话级 Token 效率，号称账单降三成。Shannon 偏生产环境，带多智能体编排、Token 预算和回放调试，个人用着有点重。Headroom 给了标准 MCP 服务，集成上比纯文本压缩工具顺。Trendshift 和 daily.dev 上有人测，JSON 能省 60% 到 95% Token，编程 Agent 省 20% 左右。

不过这项目处境有点尴尬。同类工具太多，用着 caveman 的人没啥动力换。MCP 代理模式倒是加了，但压缩带来的本地算力开销，加上复杂生产环境里缓存数据好不好管，还得再看看。

压缩上下文确实能省钱，但别为了省 Token 把 Agent 架构搞乱套了。
