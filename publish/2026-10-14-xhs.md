# 拆解 ai-memory-skillpack：它和无限知识库有什么区别？

AI 编程代理跨会话没记忆，重复工作没法复用。网上有些资料（像 LangChain 文档和 AI for Restaurants 博客）说，技能应该做成能版本控制、可以迭代的配方，靠日常记忆慢慢演化。但记忆库无限膨胀会让上下文退化。所以得加上限。

看项目 tudoumashu/ai-memory-skillpack（现在 496 星，日均涨 14）。本来想从 README 找点命令、文件结构或 CI 配置，但抓取失败，没拿到具体指令。不过追踪数据显示，它的核心是给 Codex/Claude Code 加一个有上限的项目记忆层，带校验机制。网上讨论（像 Dual-Memory Optimization 相关视频）提到，技能记忆演进一般靠读结构化执行轨迹，这个项目是用校验机制来做边界约束。

这不是单纯的提示词包装。静态文本做不到容量限制和状态校验。它设计了 bounded/fail-closed 模式，底层肯定有程序逻辑做拦截和验证，有真实的工程量。

几个同类项目定位不一样。trailofbits/coop 给的是一次性隔离虚拟机，属于沙箱基础设施。donvito/agent-monitor 是个桌面应用，用来看子代理树和成本。chigwell/Penelopa.ai 自底向上，从真实会话里蒸馏技能。chaseai-yt/crucible 搞四阶段交叉审查，跟记忆层不搭边。

局限也有，跟 second-brain-os 有功能重叠。fail-closed 设计保了状态安全，但容量上限可能会在长周期的科研生信流程里截断长尾上下文。这会不会影响任务连续性，不好说。

给记忆加边界、做状态校验，是 AI 代理工程化绕不开的事。这个项目算是个挺务实的控制论样本。
