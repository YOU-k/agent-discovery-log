# 拆解科学Agent技能库：165个技能怎么用

科研场景里，通用 AI agent 老卡在两件事上：够不着专业数据库，也接不上领域计算库。过去一年 GitHub 冒出一批想解决这问题的 skill 库，今天说的 Tyche-MKR/scientific-agent-skills 是其中一个。但不是唯一值得聊的。

按 README 自述，它要把任意 AI agent 变成 AI Scientist，定位是"科学领域的头号 Agent Skills 库"，说覆盖生物学、化学、医学和药物发现，兼容 Cursor、Claude Code、Codex、Pi、Antigravity 以及开放的 Agent Skills 标准。第三方目录站 AgentMatter 的描述是"160 多个面向科研工作的 agent skill，覆盖研究数据库、分析工具和科学写作流程"；Claudeers 的说法是这些技能让 agent 能直接调用专业科学库、数据库和工具。这些是项目自述和目录站的转述，不是独立测评。

拆解部分得先说明：这次 README 抓取失败，所以拿不到命令、文件结构、scripts/tests/CI 这些一手证据。能确认的只有网页标题和简介里的数字：165 个"ready-to-use validated skills"、100 多个科学数据库接口、声称 19 万科学家在用。这些技能到底是 prompt 文件、脚本还是带依赖的模块，有没有测试和 CI，素材里没有，不能替它下结论。

所以工程含量只能给出有限判断。可核验的硬指标目前就两个数字（165 与 100+）加一份兼容性清单；README 证据缺失，没法确认存在 scripts、tests 或 CI 流水线，也就不能判定它是真实工程还是提示词包装。补上仓库文件级证据之前，把它当"说明书型项目"看更稳妥。

横评看定位差异。K-Dense-AI/scientific-agent-skills 星数 45060、契合度 9/10，同样是 165 个技能加 100 多个数据库，但更偏科学计算和数据库，生信味最重；InternScience/Awesome-Scientific-Skills 星数 548，是精选合集加 skill 生成与评测两个配套工具，比纯 awesome 列表更工程化；yorkeccak/scientific-skills（61）和 drpedapati/sciclaw（88）都是本项目的克隆或衍生。得指出一点，追踪数据显示本项目与 K-Dense-AI 同名，重复度判断为"同一项目"——也就是说，这可能不是两个独立项目在竞争，而是同一份技能库的不同仓库。这直接影响该给谁点星。

开放问题有三个。165 个技能是否经过验证、由谁验证，素材里只有 README 自称的 validated。19 万科学家的使用数据没有出处。本项目首次发现于 2026-09-06，日均涨星约 1，跟 K-Dense 的 4.5 万星差距巨大，同名关系不澄清，星数就没法当作质量信号。

一个技能库的价值不在技能数量，而在每个技能是否可被独立复现和检验。
