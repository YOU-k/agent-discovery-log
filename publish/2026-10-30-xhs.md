# 拆解 claude-mem：AI助手的跨会话记忆

AI 编程助手单次会话能处理复杂任务了，但跨会话丢上下文还是很烦。每次开新会话都得重新解释项目进度。thedotmack/claude-mem 就是来补这块短板的，2026 年 10 月发现到现在星标 104,819。它想给 AI 编程助手加上跨会话记忆。Hacker News 上关于“Claude’s memory architecture is the opposite of ChatGPT’s”的讨论里，不少开发者也在关注这种记忆架构的差异。

实现上，claude-mem 是个持久记忆压缩系统。README 里写的核心机制三步：捕获 agent 会话里的操作，用 AI 压缩记录，后续会话注入上下文。项目用 TypeScript 写的，基于 Claude Agent SDK，要求 Node 大于等于 20.0.0。README 没放 scripts 或 CI 配置，但版本已经迭代到 15.7.0，支持 Claude Code、Codex、Gemini、Copilot 好几个平台。

这项目不是简单套个提示词。捕获、压缩、再注入的流程需要底层存储和调度。跨平台还得抽象不同 agent 接口，统一管上下文注入。版本到 15.7.0 了，加上在科研生信流程里确实能记住之前的分析进度，说明它是真有东西，不是写个说明书就算了。

跟同类项目比，claude-mem 定位很不一样。zarazhangrui/codebase-to-course 是把代码库变成交互式 HTML 课程，claude-mem 是做底层记忆。ythx-101/live-panel-skill 拿 JSON 配置生成动态架构图，算可视化。xianyu110 的 ecommerce-video-skills 和 ecommerce-image-skills 是做电商带货的，跟科研生信没关系。claude-mem 胜在作为基础设施层，能提供跨平台持久记忆。

当然也有局限。压缩肯定会掉信息，AI 压缩没准就把关键代码细节丢了。Hacker News 那个“Show HN: Recall: Give Claude memory with Redis-backed persistent context”讨论里，大家也在找持久化记忆更好的存储方案。跟 mksglu/context-mode 功能有些重合，claude-mem 多了跨平台，但单平台深度适配上会不会打折不好说。

claude-mem 工程实现是挺靠谱的，但怎么在多 agent 压缩里平衡无损性和检索相关性，还得接着看。
