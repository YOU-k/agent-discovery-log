# 拆解 academic-research-skills-codex：一次移植，值不值得装

同一套学术研究技能包，GitHub 上有两个仓库，一个 Claude Code 版，一个 Codex 版。Claude 版 49,472 star，Codex 版 11,639。功能一样，只是跑的平台不同。这种事值得单独说一次，因为背后是个更普遍的问题：换壳项目到底要不要跟。

先看这个领域本身的毛病。用 AI 做科研，卡点不在模型强弱，在流程管不住。文献哪来的、审稿标准谁定的、改了什么留没留痕，这些没有结构化约束的话，产出的就是一堆看着合理但追不回去的字。academic-research-skills 想解决的就是这个，Codex 版是它的平台移植。

拆一下实现。先说清楚：这次 README 没抓到，所以下面依据的是同作者 Claude 版的公开文档和第三方索引页。Claude 版 docs/SETUP.md 写明了插件平台范围，Claude Code CLI、VS Code 扩展、JetBrains 扩展是完整支持；claude.ai 网页版、Claude for Work、直接调 Anthropic API 不支持插件，得改用 Method。安装命令这块，AI SkillHub 页给的 Codex 版装法是在项目根目录跑 npx bzskills add Imbad0202/academic-research-skills-codex --skill academic-research-suite，另外也提供 ZIP 包解压到本地 Skills 目录。功能描述上，Codex 仓库自己的说法是 Codex-native Academic Research Skills suite，面向 human-in-the-loop 工作流，强调 evidence-bound review and revision，保留 durable evidence rows、已确认的审稿标准、非排名式路线图、作者裁决和修改证据包。第三方页面 Skillselion 提到同作者的 academic-paper 有 6,505 次安装、38,127 star。能核实的就这些。

工程含量怎么看。就现有证据，这更像提示词加流程说明书的包装，不是独立工程实现。三点依据：一，README 全文没拿到，scripts、tests、CI 配置、目录结构全都无法确认，而真项目一般会在 README 里直接摆出来；二，已拿到的文档描述全集中在工作流概念上——证据行、审稿标准、路线图、裁决、证据包，这些是流程规约，不是可执行代码的证据；三，安装就一条 npx 命令加 ZIP 解压，没有编译、依赖管理、构建步骤的描述。不是说它没价值，但价值在流程约束的设计，不在工程复杂度。

横向比一下。Claude 原版 academic-research-skills 从找文献到定稿全覆盖，功能最全但偏通用，缺生信专用流程；AAASS554/codex-academic-paper-skills 是本科软工毕业论文场景，规划、降重、中文降 AIGC，更垂直；franklee16 和 YuanyuanMa03 的同名仓库 star 分别 219 和 69，属于同一命名下的跟随者，这里不展开。Codex 版本身，和 Claude 版功能等价，只是换了运行环境。

局限和没答案的问题。没有 README，就没法验证它是否真实现了承诺的证据链机制，也判断不了 Codex 平台的能力差异有没有带来功能缺失。更实际的问题是重复度：它和 Imbad0202/academic-research-skills 是同一套内容，装一个就够。追新项目之前，先想清楚自己主要用哪个平台。

一句话：这不是新工具，是移植。除非你主用 Codex，否则不用再装一遍。
