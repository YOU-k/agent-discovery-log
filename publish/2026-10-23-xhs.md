# 拆解 claude-howto：它和官方文档的区别

去年 GitHub 上一堆项目在解决同一个问题。luongnv89/claude-howto 星数很高，43178 颗。Anthropic 推了 Claude Code on the web 简化终端操作，但本地工作流编排没人管：官方文档只说有什么功能，不讲怎么把斜杠命令、hooks、记忆和子智能体拼成工作流，学习路径和进阶示例也缺。这个项目就是填这个坑的。

README 里能看到，它搭了一条结构化的进阶路线，不只是堆命令。10 个教程模块，从基础命令到自定义智能体团队。配置模板可以直接复制粘贴——斜杠命令、CLAUDE.md 模板、hook 脚本、MCP 配置、子智能体定义都有。文档里嵌了 Mermaid 流程图帮你看懂逻辑。仓库还有 LEARNING-ROADMAP.md 和 CATALOG.md，终端里跑 /self-assessment 或 /lesson-quiz hooks 能做交互式自测。整套学下来大概 11 到 13 小时。

说白了这是个提示词和配置模板的教程仓库，不是底层基础设施项目。核心交付物就是 Markdown 文档、Mermaid 图、配置模板和教学脚本，没有复杂业务逻辑代码，也没有自动化测试。价值在于把 Claude Code 的功能系统地理了一遍。

跟 anthropics/skills 这类官方技能包比，区别在于它做系统化教学。技能包给单一功能模块，这个项目给完整学习路径。Hacker News 上有人讨论过，焦点是怎么通过 MCP 教 Claude 干特定任务。所以技能包适合按需取用的人，这个项目更适合从零搭科研智能体或复杂自动化工作流的初学者。

局限也很明显，项目绑死了 Claude Code 的功能边界。Anthropic 一更新 Claude Code on the web 或底层 API，本地的 hook 脚本和 MCP 配置可能跟不上。四万多颗星的活跃度到底怎样，跨语言版本同步准不准，都还得再看。

系统化编排文档本身也算知识工程，至少让普通开发者用上这些 AI 工具没那么费劲。
