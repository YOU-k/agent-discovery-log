# 拆解 sepia：去 AI 味为什么先改结构

过去一年 GitHub 上冒出来不少针对"AI 味写作"的工具，大多是在替换词表上做文章：删掉"值得注意的是""在当今快速发展的时代"，把破折号改成逗号。但改完读一遍，还是像机器写的。今天要讲的 sepia 是这类项目里星数比较高的一个，官方定位是"面向代码生成类 LLM 的去 AI 味写作技能"，支持 Claude Code、Codex CLI、ChatGPT 等兼容 Agent Skills 的环境。它值得单独拿出来说，是因为处理顺序和多数同类反着来。

先说这个领域的问题在哪。去 AI 味工具的默认假设是"味道来自措辞"，但真实写作里更刺眼的是叙事层面的空洞：段落之间没有真正的推进关系，论点按模板排布，每一节都在平均用力。这类问题不是换词能解决的。sepia 的切入点是叙事架构，官方描述是"先修叙事结构，再改措辞"，并声称对小说和特定场合文本分别应用不同的架构修复技术。

拆一下它的实现方式。需要说明，这次抓取 README 正文失败了，下面这些证据来自项目页和第三方收录页的公开描述。第一，它是 skill 形态，不是独立应用，按 Agent Skills 规范被编码 agent 调用——也就是说它本身不含模型推理，而是一套注入上下文的指令和流程。第二，项目已经迭代到 v0.11.0，从版本号看维护频率不低，第三方追踪站记录其更新时间为 1 天前。第三，自 v0.4.0 起，sepia 定义了一个接口，允许在它之上叠加一个"声音或风格"技能，比如极简主义方法、品牌语气、人设指南；这个叠加是 opt-in 的，需要显式告知 sepia 当前有风格技能在场。这一点是它和纯词表工具最实质的差异：它把自己放在结构层，把风格层让出去。

工程含量怎么看。基于现有素材，sepia 属于"提示词与方法论包装"，不是有真实工程系统的项目。判据有三条：它是 skill，不是带构建产物的代码库，素材里没有任何命令、文件结构、scripts、tests 或 CI 配置的证据；它的核心资产是叙事架构修复这类方法论描述，不是可测试的算法模块；它的扩展方式是声明式接口叠加，不涉及运行时逻辑。这不构成贬义，skill 品类的价值本来就在流程设计，但把它当软件工程成果来评估会失焦。

横评几个同类，只看定位差异。blader/humanizer 和 Humanizer-zh 是典型的词表和句式层工具，sepia 在它们之上多了结构层修复，这是它相对更深的地方。zarazhangrui/codebase-to-course 方向完全不同，把代码库转成可滚动学习的交互式 HTML 课程，重点是生成学习课程而不是技能集合。viettranx/3dviz-pro-max 把想法转成 Three.js 或 Blender 的三维场景，填补的是可视化展示这块空白。tradermonty/claude-trading-skills 做股票与 ETF 的分析和交易复盘，与 TradingAgents 同类但更轻，不做实时撮合。sv-number/skills 让 agent 下单手机号并接收验证码，填补的是手机验证自动化。这几者之间没有直接竞争关系，sepia 的差异点在写作链路的结构层。

局限和开放问题。叙事架构修复的效果高度依赖被处理文本的类型，论文和 report 与小说的架构标准并不一致，官方称按场合区分，但没有可核验的评测数据。opt-in 的风格叠加接口依赖使用者的显式配合，实际调用中容易被忽略。另外，作为一个无测试、无 CI 的 skill，它的迭代质量只能靠版本号和用户反馈间接判断。

它解决的是换词工具解决不了的那一层问题，而这一层恰好最难验证。
